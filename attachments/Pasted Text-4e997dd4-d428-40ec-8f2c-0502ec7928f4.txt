## While you are here — the app must also meet these deploy rules
- Dockerfile at the project ROOT, starting with `FROM <base-image>` and a `CMD`/`ENTRYPOINT` that starts the server.
- Listen on host `0.0.0.0` and the `PORT` env var (`process.env.PORT`, always 8080) — NOT `127.0.0.1`/`localhost`.
- A long-running server (it must not run once and exit).
- Read all config from environment variables — never commit secrets. These env vars are injected by the platform and are read-only — do NOT set or hardcode them: `PORT` (always 8080), `DATABASE_URL`, and any `META_*`. Your own keys (e.g. `OPENAI_API_KEY`) go in the app's Env vars panel.
- If the app uses a database, read `process.env.DATABASE_URL` (the platform injects it) — do NOT bundle a database, hardcode credentials, or point at `localhost`.
- Log to stdout/stderr (`console.log`/`print`), never to files: those two streams are the only place the platform reads the app's logs from.
- The container disk is wiped on every deploy and restart, so keep data in the database (`DATABASE_URL`) and uploaded files in an external object store. No local files, SQLite or embedded database as storage, and no `VOLUME` in the Dockerfile.
- The image may take at most 15.00 GB (15000000000 bytes) unpacked (all layers after decompression, what it takes on disk): add a `.dockerignore` and use a multi-stage build so only what the app runs ships.
